# ADR 0001: Основа MVP

- Статус: принято
- Дата: 2026-08-28

## Контекст

Приложение КФУ ЭлЖур должно работать на Android и iOS из единой кодовой базы, показывать расписание группы и преподавателя, работать без сети и хранить личные заметки и задания. Финальный дизайн закрепляет пять вкладок: «Сегодня», «Расписание», «Задания», «Заметки» и «Профиль».

Пользователь подтвердил MVP для 14 институтов и академий с основной страницы расписания, без колледжей. Видимый вход и регистрация не используются.

## Решение

Используется модульный монолит на .NET 10:

- .NET MAUI и XAML для мобильного интерфейса;
- `Mobile.Core` для тестируемых ViewModel, офлайн-сценариев и синхронизации;
- ASP.NET Core Web API для каталога, расписания и личной синхронизации;
- отдельный Worker для импорта официальных расписаний;
- PostgreSQL и Entity Framework Core на сервере;
- SQLite как локальный источник данных мобильного интерфейса.

Проекты зависят друг от друга только в следующем направлении:

```text
Domain              -> ничего
Application         -> Domain
Infrastructure      -> Application + Domain
Api / Importer      -> Application + Infrastructure + Contracts
Mobile.Core         -> Contracts
Mobile              -> Mobile.Core + MAUI
```

## Первый запуск

До показа основной навигации приложение проводит пользователя через шаги:

```text
Институт -> Направление -> Группа -> Подгруппа -> Загрузка -> Сегодня
```

Подгруппа является необязательным шагом. Выбранные идентификаторы и отображаемые названия сохраняются локально, чтобы профиль был доступен без сети. Новая группа становится активной только после успешной загрузки её расписания.

## Личные данные без логина

При первой синхронизации сервер создаёт `ClientInstallation` и возвращает непрозрачный секрет установки. Мобильное приложение хранит его в `SecureStorage`; пользователь не видит экрана входа. Сервер ограничивает заметки и задания этой установкой.

Такая схема не является аккаунтом и не обеспечивает перенос данных на другое устройство или восстановление после потери секрета. Эти возможности требуют отдельного механизма идентичности после MVP.

## Расписание и время

Сервер хранит конкретные `LessonOccurrence`, исходные значения и происхождение записи. Номер пары задаётся через `TimeSlot`; точное время зависит от подразделения, корпуса и периода действия. Мобильный клиент вычисляет текущую и следующую пару из SQLite, поэтому эта функция работает офлайн.

Расписание преподавателя строится из импортированных групповых расписаний. Каталог преподавателей и варианты написания ФИО формирует импортёр.

## Последствия

- Telegram, BotFather, OpenID Connect и пользовательские Telegram-поля отсутствуют.
- API и импортёр можно развивать и тестировать независимо от MAUI UI.
- Личные изменения отправляются через идемпотентную очередь синхронизации.
- Для production понадобится постоянно доступный Linux-хост; Ubuntu VM на компьютере не требуется для начала разработки.
