# PWA-версия «КФУ ЭлЖур»

PWA — дополнительный устанавливаемый веб-клиент. Нативный проект `.NET MAUI` остаётся основным мобильным клиентом и не заменяется веб-версией.

## Возможности

- пять вкладок из согласованного дизайна: «Сегодня», «Расписание», «Задания», «Заметки» и «Профиль»;
- первый запуск без авторизации с выбором института, направления, курса, группы и подгруппы;
- актуальное расписание из официального API КФУ и поиск по справочнику преподавателей;
- выбор дня нажатием на дату или день недели, недельный режим и показатель чётности недели;
- горизонтальные свайпы между пятью основными вкладками без блокировки вертикальной прокрутки и элементов форм;
- локальные заметки и задания с созданием, редактированием, удалением и привязкой к паре;
- IndexedDB-кэш, локальная очередь изменений, статус готовности и отдельная загрузка полного расписания группы для работы без сети;
- светлая и тёмная темы, адаптивная вёрстка для iPhone, Android и настольного браузера.

Локальные данные PWA принадлежат конкретному профилю браузера. Очистка данных сайта удалит профиль, заметки, задания и несинхронизированные изменения. Браузерное хранилище не предоставляет тех же гарантий, что Android Keystore или iOS Keychain в MAUI-приложении.

## Подготовка офлайн-версии

1. При первом запуске подключитесь к интернету и выберите учебную группу.
2. Откройте вкладку «Профиль» и нажмите «Скачать данные для офлайна».
3. Дождитесь зелёного статуса «Готово». Он означает, что полное расписание группы сохранено в IndexedDB, а Service Worker проверил наличие всех файлов приложения.
4. На iPhone добавьте PWA на экран «Домой». После этого её можно закрыть, включить авиарежим и запустить с иконки для контрольной проверки.

Кнопка «Обновить офлайн-данные» повторно получает расписание КФУ и проверяет кэш. Если сеть временно недоступна, приложение сохраняет последнюю корректную копию и сообщает, готова ли она к автономной работе.

## Локальный запуск

```powershell
dotnet run --project src/UniversitySchedule.Web
```

Откройте адрес из консоли. Для проверки установки и service worker используйте Release-публикацию через HTTPS либо `localhost`:

```powershell
dotnet publish src/UniversitySchedule.Web/UniversitySchedule.Web.csproj -c Release -o artifacts/pwa
```

Каталог преподавателей генерируется перед сборкой из проверенного файла MAUI-проекта и отдельно в Git не хранится.

## Установка на iPhone

1. Откройте опубликованный HTTPS-адрес в Safari.
2. Нажмите «Поделиться».
3. Выберите «На экран Домой», затем «Добавить».

Это бесплатный способ открыть приложение на физическом iPhone без TestFlight и Apple Developer. PWA не является подписанным `.ipa`: возможности iOS, которым требуется нативная подпись, в ней недоступны.

## GitHub Pages

Workflow `PWA` проверяет сборку на каждом pull request и публикует приложение после изменения ветки `main`. Для первой публикации владелец репозитория должен один раз открыть `Settings → Pages` и выбрать `Source: GitHub Actions`. После успешного запуска адрес будет:

`https://l0naroff313.github.io/cfu-schedule-app/`

API сервера можно подключить только по HTTPS через `UniversityScheduleApi:BaseUrl` в `wwwroot/appsettings.json`. API уже разрешает origin GitHub Pages из `Cors:AllowedOrigins`; для другого домена добавьте его origin в этот список или через переменную окружения. Без сервера расписание, заметки и задания продолжают работать локально; сервер нужен для синхронизации между устройствами.

## Cloudflare Pages

Основной публичный адрес можно перенести с `github.io` на бесплатный HTTPS-адрес вида `https://<project>.pages.dev/`. Приложение остаётся статической Blazor WebAssembly PWA: банковская карта, домен и постоянно работающий сервер для её файлов не нужны. GitHub Actions собирает .NET-проект, а Cloudflare получает только готовые статические файлы.

1. Создайте бесплатный аккаунт Cloudflare и откройте `Workers & Pages`.
2. В профиле Cloudflare откройте `API Tokens → Create Token → Custom token` и выдайте только разрешение `Account → Cloudflare Pages → Edit` для своего аккаунта.
3. Скопируйте `Account ID` из обзорной страницы Cloudflare. API-токен показывается один раз; не отправляйте его в чат и не сохраняйте в проекте.
4. В `Settings → Secrets and variables → Actions` репозитория добавьте:

   | Тип | Имя | Значение |
   | --- | --- | --- |
   | Repository variable | `CLOUDFLARE_PAGES_PROJECT` | Уникальное имя, например `cfu-eljournal-l0naroff313` |
   | Repository variable | `CLOUDFLARE_ACCOUNT_ID` | Идентификатор аккаунта Cloudflare |
   | Repository secret | `CLOUDFLARE_API_TOKEN` | Созданный API-токен |

5. Откройте `Actions → PWA → Run workflow`. Первая публикация создаст Direct Upload project, последующие изменения `main` будут публиковаться автоматически.

Cloudflare Pages распознаёт сборку без верхнеуровневого `404.html` как одностраничное приложение и направляет неизвестные маршруты в корень. GitHub Pages получает отдельную сборку с `404.html` и остаётся резервным адресом.

Если будет подключён ASP.NET Core API для межустройственной синхронизации, добавьте новый origin в `Cors:AllowedOrigins`, например через `Cors__AllowedOrigins__1=https://cfu-eljournal-l0naroff313.pages.dev`. До этого расписание, профиль, заметки и задания продолжат работать локально в PWA.
