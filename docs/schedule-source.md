# Источник расписания КФУ

## Архитектурное заключение

Официальная страница `https://cfuv.ru/raspisanie/` использует собственный публичный JSON API КФУ. Это более надёжный первичный источник, чем разбор HTML или отдельных таблиц: каталог, сетка звонков, календарь чётных/нечётных недель и занятия уже представлены структурированными данными.

Основные маршруты:

- `GET https://cfuv.ru/wp-json/cfu/v1/sched/index` — институты/факультеты, направления, курсы, группы, звонки и учебные недели;
- `GET https://cfuv.ru/wp-json/cfu/v1/sched/group?code={код}` — занятия выбранной группы;
- `GET https://cfuv.ru/wp-json/cfu/v1/sched/find?by=teacher&q={строка}` — поиск и расписание преподавателей.

API не требует авторизации. Мобильное приложение обращается к нему через HTTPS и сохраняет только успешно разобранные ответы в SQLite. Если сеть или источник недоступны, используется последняя локальная копия; ошибочный ответ не заменяет рабочий кэш.

## Преобразование данных

`index.bells` задаёт время начала и окончания по номеру пары. `index.weeks.ch` и `index.weeks.nch` содержат даты понедельников чётных и нечётных учебных недель. Для регулярного занятия конкретная дата вычисляется как понедельник соответствующей недели плюс `день - 1`.

Правила источника:

- `чёт` — только даты из `weeks.ch`;
- `нечёт` — только даты из `weeks.nch`;
- `обе` — объединение обеих последовательностей;
- поле `дата` имеет приоритет и задаёт одно конкретное занятие;
- факультетское событие `fak` является конкретным событием: используется начало `период` плюс `день - 1`;
- подгруппа `0` относится ко всей группе, а `1` и `2` фильтруются по выбору пользователя;
- время интерпретируется в часовом поясе университета UTC+03:00 и сохраняется как UTC.

Стабильный локальный идентификатор формируется детерминированно из группы, даты, номера пары, подгруппы, предмета, вида, преподавателей и места. Повторная загрузка того же ответа не создаёт дубликаты.

## Кэш мобильного приложения

SQLite-таблица `cache_documents` хранит:

- актуальный документ `index`;
- отдельный документ расписания каждой загруженной группы;
- результаты выполненных поисков преподавателей;
- выбранный учебный профиль;
- UTC-время последнего успешного обновления каждого документа.

Стратегия чтения — network first с безопасным fallback на SQLite. При запуске уже выбранной группы сначала доступна локальная копия, затем приложение пытается обновить её.

## Ограничения и резервный путь

- API не публикует формальную схему или SLA, поэтому ответы валидируются до записи в кэш.
- Не у всех занятий заполнены корпус и аудитория; приложение показывает «Аудитория не указана» и не дополняет данные вымышленным справочником.
- Поиск преподавателя выполняется от двух символов и кэшируется по нормализованному запросу.
- Списки и расписание отражают только опубликованные на текущий момент данные КФУ.
- XLS/XLSX и официальный Nextcloud остаются резервным источником для будущего серверного импортёра, если JSON API исчезнет или окажется неполным.

Для текущего мобильного среза отдельный сервер не нужен. Production-сервер потребуется позже для синхронизации личных заметок между устройствами, централизованного мониторинга источника и резервного импорта.
