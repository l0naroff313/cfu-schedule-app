# Источник расписания КФУ

## Архитектурное заключение

Страница `https://cfuv.ru/raspisanie/` перенаправляет на `https://schedule.cfuv.ru/`. Публичный WordPress REST API предоставляет метаданные подразделений и направлений, но не полноценные записи занятий.

Сами расписания публикуются как XLS/XLSX-файлы в официальном Nextcloud КФУ. Публичные ресурсы доступны через WebDAV, который возвращает ETag, дату изменения, имя и размер файла. Поэтому основной источник данных для импортёра — опубликованные таблицы, а HTML используется только для обнаружения актуальных ссылок.

## Конвейер

```text
WordPress REST / страницы подразделений
    -> ссылки публичных ресурсов Nextcloud
    -> WebDAV metadata и условная загрузка
    -> адаптер XLS/XLSX
    -> канонический снимок
    -> полная валидация
    -> staging
    -> транзакционный upsert в PostgreSQL
```

Импорт обязан:

- не загружать повторно документ с неизменившимся ETag;
- хранить хэш, метаданные и происхождение документа;
- повторно обрабатывать один снимок без создания дублей;
- не менять рабочие данные при ошибке загрузки, разбора или валидации;
- помечать исчезнувшие занятия только после успешного полного снимка;
- сохранять исходный свободный текст отмен, замен и диапазонов дат;
- отправлять неизвестные конструкции в журнал `ImportIssue`, а не угадывать их смысл.

## Обнаруженные варианты формата

- `.xlsx` и устаревший `.xls`;
- отдельные области для чётной и нечётной недели;
- объединённые ячейки и повторяющиеся блоки строк;
- одна или две подгруппы;
- номер пары без обязательного времени начала и окончания;
- произвольные пометки об отменах, заменах и датах проведения.

Из-за различий применяется набор адаптеров, а не один парсер по фиксированным координатам. Первый вертикальный срез реализуется для одного проверенного формата, затем подключаются остальные подразделения.

## Ограничения MVP

- Поддерживаются 14 институтов и академий с основной страницы, колледжи не входят в первый выпуск.
- Расписание преподавателей выводится из групповых файлов.
- Расписание звонков задаётся по подразделению или корпусу и должно иметь период действия.
- У источника нет гарантированных стабильных идентификаторов занятий, поэтому ключ записи формируется в области конкретного источника и учебного периода.
